# NotchHub v0.6.0 — Personal build

## Personal build — not notarized

This release is for personal use. It is ad-hoc signed with App Sandbox and Hardened Runtime enabled, but it is not Developer ID signed or Apple-notarized. macOS may require Finder **Open** or **System Settings → Privacy & Security → Open Anyway** on first launch. Do not disable Gatekeeper.

## What is new since v0.5.0

### M2.1 — Shelf Foundation

NotchHub now includes its first functional Shelf slice for files and folders:

- open Shelf from the Expanded Home surface;
- open Shelf while active media remains available in Expanded;
- select files and folders through the native `NSOpenPanel`, including multi-selection;
- drag local file URLs into Shelf;
- keep Shelf items across relaunches using persistent security-scoped bookmarks;
- suppress duplicate references;
- Open an item or Show it in Finder;
- Remove a Shelf reference without deleting or moving the original file/folder;
- refresh stale bookmarks when macOS reports them stale;
- reset routing to Home when leaving Expanded while preserving Compact/Peek media-first behavior.

The Shelf implementation is event-driven and does not introduce recurring polling, filesystem scanning, global keyboard/drag/scroll monitors, telemetry or network access.

## Security posture

This release keeps the shipping application deliberately constrained:

- App Sandbox enabled;
- Hardened Runtime enabled;
- exact shipping file entitlement is read-only user-selected access: `com.apple.security.files.user-selected.read-only`;
- no broad read-write file entitlement;
- no network entitlement or runtime network/WebKit client;
- no telemetry, analytics, advertising, licensing backend or remote-control channel;
- no Automation/Apple Events, Accessibility, Input Monitoring or Screen Recording requirement;
- no dynamic-code or plug-in loading exception;
- Shelf Remove never mutates the source item;
- Open/Reveal and stale-bookmark refresh use short-lived security-scoped access and fail closed when scope cannot be obtained;
- development MediaBridgeProbe/transport candidates retain separately reviewed narrower policies and are not bundled into the shipping app.

The release is ad-hoc signed. The signature protects bundle integrity after build, but it does **not** establish an Apple-verified developer identity and the release is **not notarized**.

## Installation and first launch

1. Download `NotchHub.dmg` from this GitHub Release.
2. Verify it against the accompanying `NotchHub.dmg.sha256` checksum if desired.
3. Open the DMG and place `NotchHub.app` in Applications.
4. Open the application using Finder **Open**.
5. If macOS blocks the first launch, use **System Settings → Privacy & Security → Open Anyway** and confirm the standard macOS prompt.

Do not disable Gatekeeper or weaken macOS security settings globally.

## Provenance

The release workflow publishes together:

- `NotchHub.dmg`;
- `NotchHub.dmg.sha256`;
- `build-metadata.json` containing the exact release source commit, build number, toolchain/runner data, artifact sizes, checksum and distribution-trust flags.

Published tags/releases are treated as immutable. A defect is fixed in a new version rather than silently replacing an existing artifact.

## Known limitations

- Shelf v0.6.0 intentionally handles files/folders only; text/URL snippets belong to the future M3 Snippets module.
- Shelf does not yet include Quick Look, native Share services, Shelf multi-selection actions, copy/move/rename/delete or linked-folder browsing.
- Calendar and Translator remain planned modules.
- Settings remains the bounded four-control slice introduced in v0.5.0.
- Because this Personal Release is not Developer ID signed/notarized, first-launch trust warnings for a downloaded copy are expected.
- Trusted Developer ID/notarized distribution remains an optional future tier.
