# NotchHub v0.5.0 — Personal build

## Personal build — not notarized

This release is for personal use. It is ad-hoc signed with App Sandbox and Hardened Runtime enabled, but it is not Developer ID signed or Apple-notarized. macOS may require Finder **Open** or **System Settings → Privacy & Security → Open Anyway** on first launch. Do not disable Gatekeeper.

## What is new since v0.4.0

Everything below was implemented, automated-tested (where feasible), physically accepted (where a real system side effect required it) and merged since `v0.4.0`, and is included in this version for the first time:

- **M7 — first bounded Settings slice** — a new "Settings…" item in the menu bar opens NotchHub's first ordinary window, with four controls:
  - **Launch at Login**, backed by the modern `SMAppService` API.
  - **Reduce Motion override** (System / Always On / Always Off), independent of the system Accessibility setting.
  - **Manual display selection**, overriding the automatic hardware-notch-first display policy for the panel.
  - **About**, showing the current version and a link to the latest GitHub Release.
  
  This is the app's first persisted setting (stored locally via `UserDefaults`, no new entitlement, no telemetry).
- **Real UI-level test coverage for the Settings window** — automated tests now open Settings through the actual menu-bar path and verify the window and its controls, alongside a fix ensuring UI tests never touch a real user's saved preferences.
- **Housekeeping fix**: the app's checked-in version string (shown e.g. in the new About section when running outside a full release build) now stays in sync with the published version automatically checked by tests.

## Security posture

This personal build remains deliberately constrained:

- App Sandbox enabled;
- Hardened Runtime enabled;
- no telemetry, analytics, advertising, licensing backend, or remote-control channel;
- no direct runtime network/WebKit API;
- no runtime shell/subprocess execution beyond the existing reviewed, fixed-path system media adapter;
- no dynamic code or plug-in loading;
- no global keyboard, button, drag, scroll, or modifier monitoring;
- global pointer (`mouseMoved`) observation is bounded to an actual in-progress NotchHub interaction rather than persistently armed in idle;
- no bundled credentials, API keys, certificates, or private keys;
- the new Settings persistence uses only the standard, sandboxed `UserDefaults` — no new entitlement, no shared container, no inter-process surface.

The release is ad-hoc signed. The signature protects bundle integrity after build, but it does **not** establish an Apple-verified developer identity and the release is **not notarized**.

## Installation and first launch

1. Download `NotchHub.dmg` from this GitHub Release.
2. Verify it against the accompanying `NotchHub.dmg.sha256` checksum if desired.
3. Open the DMG and place `NotchHub.app` in Applications.
4. Open the application using Finder **Open**.
5. If macOS blocks the first launch, use **System Settings → Privacy & Security → Open Anyway** and confirm the launch through the standard macOS prompt.

Do not disable Gatekeeper or weaken macOS security settings globally.

## Provenance

The release publishes these assets together:

- `NotchHub.dmg` — application installer;
- `NotchHub.dmg.sha256` — SHA-256 checksum;
- `build-metadata.json` — source commit, build number, runner/toolchain versions, artifact sizes, checksum, and explicit distribution-trust flags.

A published version/tag is immutable. If a defect is found, it will be fixed in a new version rather than silently replacing this release artifact.

## Known limitations

- Shelf, Snippets, Calendar, and Translator modules are not implemented yet.
- Settings currently covers only the four controls above; additional preferences (theme/color customization, keyboard shortcuts) remain deferred to a future slice.
- Physical acceptance for the marquee-text feature (M6.9, released in `v0.2.0`) was explicitly waived by the product owner rather than performed on real hardware before merge; see `docs/testing/M6_9_MEDIA_MARQUEE_ACCEPTANCE.md` for the recorded residual risk.
- Because this build is not Developer ID signed/notarized, macOS trust warnings on first launch are expected for a downloaded copy.
- Trusted Developer ID/notarized distribution remains an optional future tier if Apple Developer Program membership becomes worthwhile.
